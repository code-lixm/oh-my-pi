**任务以逐字内容字符串引用，NEVER 使用自动生成的 ID；不存在“task-1”/“task-N”。在 `task` 字段中传入内容文本。**

每次完成时，最早仍未完成的任务（按阶段顺序）会自动升为 `in_progress`。
乱序完成可能将此指针**移回**较早阶段；这是预期行为，已完成任务绝不会回退。

## 操作

|`op`|必填字段|效果|
|---|---|---|
|`init`|`list: [{phase, items: string[]}]`|初始化完整列表（替换现有列表）|
|`init`|`items: string[]`|扁平单阶段初始化|
|`start`|`task`|标记为进行中|
|`done`|`task`|标记一个任务完成；拒绝按阶段完成|
|`drop`|`task` 或 `phase`|标记为已放弃|
|`block`|`task` 或 `phase`，可选 `reason`|标记为**阻塞**：保持开放、等待外部输入；不参与停止时未完成待办提醒|
|`unblock`|`task` 或 `phase`|将阻塞任务恢复为 `pending`|
|`rm`|`task` 或 `phase`（可选）|移除任务或阶段；两者均省略时清空|
|`append`|`phase`、`items: string[]`|向阶段追加任务；按需惰性创建|
|`view`|—|只读：回显列表|

## 结构
- **任务内容：** 5–10 个词；说明做什么，而非如何做。唯一标识符。
- **阶段名称：** 简短名词短语（例如 `Foundation`、`Auth`、`Verification`）。唯一标识符。NEVER 加 `1.`、`A)`、`Phase 1:` 前缀。

## 规则
- 每个任务完成后立即标记；同一轮开始下一个开放任务。NEVER 批量关闭阶段。
- 子代理结果是账本边界：下一个动作前核对已完成任务。
- 实现证据只能关闭实现任务；验证在命令成功前保持开放。
- NEVER 让 todo 调用成为本轮唯一工具调用；与下一项真实工作一起批量调用。
- 等待外部输入？`block`；可由代理解决的阻塞？`append` 一个解阻任务。
- 一旦引入，保持 `task`/`phase` 字符串稳定。
- 忘记精确任务文本？`view` 会回显列表；NEVER 凭记忆猜测。

## 何时创建列表
- 任务需要 3 个以上不同步骤
- 用户明确要求
- 用户提供了一组任务
- 任务中途收到新指令：继续前记录

<critical>
用户给出多步骤计划、分阶段待办、numbered/bulleted 清单或“N bugs/items/tasks”时：
- 开始前 MUST 用 `init` 将每个项目作为独立任务建入列表。
- 列出全部；NEVER 概括成更少项目、只挑“重要的”、遗漏项目或靠记忆追踪其余工作。
</critical>
