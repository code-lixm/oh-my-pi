通过 ast-grep 执行结构化、AST 感知的重写。当文本替换不安全时用于 codemod。混合语言路径没有问题：每个文件按自己的语言解析，模式只会重写成功解析的文件。

- `pat` 中的元变量（`$A`、`$$$ARGS`）会代入 `out`。
- **模式匹配的是 AST 结构，而不是文本。** `$NAME` = 一个节点；`$_` = 不绑定的匹配；`$$$NAME` = 零个或多个。
  - 使用 `$$$NAME`，NOT `$$NAME`（无效）。名称必须大写且是整个节点——`prefix$VAR` 无效。
- 同一个元变量出现两次 → MUST 匹配相同的代码（`$A == $A` 匹配 `x == x`，不匹配 `x == y`）。
- 重写模式 MUST 解析为单个 AST 节点。非独立片段 → 包裹为：`class $_ { … }`。
- TS：容忍注解 —— `async function $NAME($$$ARGS): $_ { $$$BODY }`。用空 `out` 删除：`{"pat":"console.log($$$)","out":""}`。
- 1:1 替换——不能拆分或合并捕获。
- 匹配处于 STAGED 提案状态，尚未应用：向 `xd://resolve`（应用）或 `xd://reject`（丢弃）写入一句理由以完成操作。
- 解析问题表示重写格式不正确，不是干净的 no-op。一次性的文本编辑优先使用 Edit 工具。
